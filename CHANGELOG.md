# Changelog

All notable changes to lablet are documented in this file.

The format is based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html). The workspace has one version. The public contract is the config schema, the outcome JSON, and the telemetry registry; a breaking change to any of them is a major version bump.

An entry under `Unreleased` is mandatory for any change to one of the three contract files, and `cargo xtask changelog` fails without it:

- `lablet/schema.json`, the config schema
- `lablet/telemetry/registry/`, the telemetry registry
- `lablet/tests/fixtures/outcome.json`, the outcome JSON fixture

## [Unreleased]

### Added

- Project scaffold: the `lablet/` Cargo workspace with an empty crate for every ring of the architecture, the root `xtask` gate crate (`lint-layers`, `lint-manifests`, `fmt`, `clippy`, `deny`, `doc`, `test`, `coverage`, `mutants`, `changelog`, `pre-commit`, `pre-push`, `ci`), the pinned Rust toolchain and `mise.toml` gate tools, `scripts/setup.sh` and the git hooks, the `cargo deny` policy, and the GitHub Actions workflow.
- Telemetry contract plumbing: the Weaver registry under `lablet/telemetry/registry/` with its justification policy, the core and GenAI semantic conventions and the shared Weaver policies and templates vendored under `lablet/telemetry/deps/` at pinned commits, `cargo xtask weaver check` in the pre-commit gate, and `cargo xtask weaver vendor [--check]`.
- Telemetry contract: the registry declares the `lablet.invoke_agent`, `lablet.chat`, and `lablet.execute_tool` spans, the `lablet.run` wide event, the `lablet.retry` span event, the `gen_ai.client.operation.exception` and `gen_ai.client.inference.operation.details` log records, and every `lablet.*` attribute with its justification. `cargo xtask weaver generate` renders the `lablet-telemetry-registry` crate and the reference under `lablet/docs/telemetry/` from it, and `cargo xtask weaver generate --check` holds them to the registry in the pre-commit gate.
- Domain model: the `lablet-model` crate holds the conversation, tool, usage, stop reason, run identity, transcript, and run summary types with their serde forms. The outcome JSON is now fixed by `lablet/tests/fixtures/outcome.json`: `duration_ms` is a whole number of milliseconds, `result.structured` and `error` are always present and `null` when there is nothing to report, and `usage.input_tokens` includes the cached tokens.
- Domain policy: the `lablet-policy` crate decides when a run stops, how long a failed provider call waits before its next attempt, and what a run's tokens cost. A limit stops the run when it's reached, not when it's passed: `max_turns: 2` stops after the tool phase of turn 2, and the timeout, the token budget, and the consecutive tool error cap stop the run on the value that equals them. `run.max_retries` counts the retries of one provider call, so `3` allows four attempts and `0` never retries. Cost prices cached tokens once, at the cache rates, and only the rest of `input_tokens` at the input rate.
- Refusals and truncation: a response the model refused, or that a content filter withheld, stops the run with the new stop reason `refused`, which exits with 2 like every reason other than `completed`. A response cut off at `max_tokens` stops the run with `output_truncated` whether or not it called tools, and none of its tool calls runs. One cut off at the context window stops it with `context_exhausted`.
- Telemetry contract: `lablet.run.stop_reason` gains the member `refused`. The `lablet.run` wide event gains `server.address` and `server.port`, present when the provider is reached over the network, and `lablet.tool_calls.unknown`, the calls to a tool name the run didn't offer; such a call counts in the totals and gets no `lablet.tool.*.<name>` key, so those keys stay bounded by what the tool executor resolves, which is the set it offered when the run was built. `lablet.provider.retries` now counts the attempts made beyond the first of a call, so a run whose only provider call fails reports none. On the `lablet.execute_tool` span, `gen_ai.tool.type` and `lablet.tool.source` are required only for a tool the run offered. `gen_ai.request.reasoning.level` follows `model.effort`, and the note of `lablet.request.bytes` says what's measured.
- Tool output cap: `tools.max_output_bytes` (default 100000, `null` for no cap) cuts a tool's output at a character boundary before the model sees it and ends it with one line that says what was cut, for every tool alike.
- Transcript: the transcript document is now `system` and `turns`. Each turn holds its input, which is the task prompt for the first turn, the model's response, a record of the provider call behind it (usage, finish reason, start offset, latency, attempts), and the outcome of each tool call it made: a status that says whether a tool ran and, when one did, where it came from and how it ended, with the start offset, latency, truncation, and the content the model was sent.
- Telemetry contract: the `lablet.execute_tool` span gains `lablet.tool.output.truncated` and, when the output was cut, `lablet.tool.output.original_bytes`; `lablet.tool.output.bytes` is the size the model was sent. Its `error.type` is `tool_error`, `unknown`, `timeout`, or `failed`, present whenever the model was sent an error result. The `lablet.run` wide event gains `lablet.tool_calls.truncated`.

- Reasoning tokens: `usage.reasoning_output_tokens` joins the outcome document and `gen_ai.usage.reasoning.output_tokens` the wide event and each chat span. Both providers report the number and both bill it at the output rate, so it's a part of `output_tokens` rather than an addition to it, exactly as the cache counts are parts of `input_tokens`. An adapter builds a `Usage` from a named `TokenCounts` rather than five positional numbers.
- Pricing on the wide event: the four rates a run was priced at are emitted beside `lablet.run.cost_usd` as `lablet.pricing.*_usd_per_mtok`, so a consumer can recompute the cost rather than trust it. A run whose provider reported cache counts above its own input count is priced for its cached tokens alone, and the rates are what let a consumer see that. Reasoning needs no rate of its own.
- Request settings on the wide event: `gen_ai.request.temperature` joins it, having been on the chat span alone, and the new `lablet.request.thinking` carries the thinking mode, its budget, and whether the reasoning text was asked for. A reasoning budget is the setting a run is most often varied by, and neither it nor the temperature reached the one row an analyst reads.

### Removed

- Telemetry contract: `lablet.provider.calls` leaves the `lablet.run` wide event and the registry. `lablet.run.turns` counts the model responses a run received, which is the same number on every row, and chat spans now number `lablet.run.turns` plus `lablet.provider.retries`, plus one when the run ended on a failed provider call.
