# Coding agents

Researched: 2026-09-18. Sources are linked inline. Everything here is an inventory of what the source emits or expects; recommendations for lablet are confined to the final section and marked as opinion.

## Span structure

| Source | Root | Children | Notes |
|---|---|---|---|
| Claude Code (beta) | `claude_code.interaction` (one per user prompt; `interaction.sequence` 1-based per process; `parent.source` = `env` when an inbound `TRACEPARENT` is honored, else `none`) | `claude_code.llm_request` (`llm_request.context` = `interaction` / `tool` / `standalone`), `claude_code.tool` → `claude_code.tool.blocked_on_user` + `claude_code.tool.execution`; `claude_code.hook` only with `ENABLE_BETA_TRACING_DETAILED=1` | Span event `tool.output` on `claude_code.tool` carries content when `OTEL_LOG_TOOL_CONTENT=1`. Every span has `span.type` equal to its name. Bash subprocesses inherit `TRACEPARENT`; `traceparent` header sent only to the Anthropic API. |
| Gemini CLI | spans keyed by `gen_ai.operation.name` ∈ `agent_call`, `user_prompt`, `system_prompt`, `llm_call`, `schedule_tool_calls`, `tool_call` | same set nested under the agent/prompt span | `gen_ai.conversation.id` = CLI session id. Detailed attributes (prompts, tool output) require `telemetry.traces=true`. |
| OpenHands SDK | No OTel tree. One span per LLM call named `llm.<model>` via Laminar (`openhands.sdk.observability.laminar.llm_call_span`), annotated with `gen_ai.usage.cost`, `gen_ai.usage.cache_read_input_tokens`, `gen_ai.usage.cache_creation_input_tokens` | — | Run structure is the persisted event list (see Events). |
| Codex | Events are emitted as `tracing` log records and as span-attached events (`log_and_trace_event!` macro emits both, with separate `log:` and `trace:` field sets); a `handle_responses` span records `otel.name`, `from`, `tool_name`, `gen_ai.usage.*` | — | No documented span hierarchy; `[otel.span_attributes]` and `[otel.tracestate.*]` config are stamped on every span. |
| Cline | None (docs: "Distributed tracing (not yet implemented)") | — | Logs + metrics only. |
| Copilot | `invoke_agent` | `chat` (one per LLM call), `execute_tool`, `execute_hook` | Standard OTel GenAI agent span names. |

## Notable design choices

- **Two-tier naming for cardinality (Claude Code, Codex).** Claude Code keeps raw `tool_name`/`query_source` and adds `tool_name_safe`, `query_source_safe`, `bash_command_class`, `bash_argv0`, `error_class` with bounded vocabularies; user-authored names collapse to `custom`/`mcp_other`. Codex bounds `originator` to a known list else `other`. Both keep high-cardinality ids (`session.id`, `turn.id`) out of most metric dimensions, with explicit `OTEL_METRICS_INCLUDE_*` opt-ins in Claude Code.
- **Content is opt-in everywhere except Gemini.** Claude Code: `OTEL_LOG_USER_PROMPTS`, `OTEL_LOG_ASSISTANT_RESPONSES`, `OTEL_LOG_TOOL_DETAILS`, `OTEL_LOG_TOOL_CONTENT`, `OTEL_LOG_RAW_API_BODIES` (`1` inline-truncated or `file:<dir>`), with a single length cap and `<attr>_truncated` / `<attr>_original_length` sidecar fields. Codex: `otel.log_user_prompt`, `[REDACTED]` literal, output preview truncated with a marker. Copilot: `captureContent` + `maxAttributeSizeChars`. Gemini defaults `logPrompts=true` and emits `function_args`, `request_text`, `response_text`. Cline hashes paths and commands rather than gating them.
- **Length even when content is redacted.** Claude Code always emits `prompt_length`, `response_length`, `tool_input_size_bytes`, `tool_result_size_bytes`; Codex `prompt_length`, `arguments_length`, `output_length`, `output_line_count`. Useful for benchmarking without storing text.
- **Correlation ids are layered.** Claude Code: `session.id` > `prompt.id` > `message.uuid` > `tool_use_id` (shared between `tool_decision`, `tool_result`, hooks, and `claude_code.tool` spans) and `request_id` + `client_request_id` pairing request to response; `event.sequence` gives a total order per process. OpenHands: `llm_response_id` groups all actions from one LLM response, `action_id` links observation to action, `parent_id` builds a tree, `tool_call_id` matches the provider call. Codex: `call_id`, `turn.id`, `tool_result_seq`.
- **Cost is computed client-side and low-precision.** Claude Code `claude_code.cost.usage` in USD (float). Codex converts an estimated USD string to `codex.turn.cost_microusd` (integer µUSD) to avoid float counters. OpenHands prefers the LiteLLM proxy `x-litellm-response-cost` header over price-table lookup. OpenHands agent-server buckets duration/tokens/cost coarsely "to avoid re-identification".
- **Decision provenance.** Claude Code `decision_source` (`config`, `hook`, `user_permanent`, `user_temporary`, `user_abort`, `user_reject`); Gemini `decision` includes `modify` and `auto_accept`; Codex `source`; Cline `auto_approved`. All treat approval as a first-class event separate from execution.
- **Split log vs trace field sets (Codex).** The same event goes to logs with rich strings (`arguments`, `output`, `agent_name`) and to spans with only numeric/bounded fields (`arguments_length`, `tool_origin`). Codex also keeps an allow-list of metrics not sent to its built-in Statsig route (`codex.api_request`, `codex.tool.call`, `codex.turn.token_usage`, `codex.turn.cost_microusd`, …) so those only reach a user-configured OTLP exporter.
- **Exporter plumbing.** Claude Code honours standard `OTEL_*` env (per-signal endpoints, `delta` temporality by default, mTLS) and blocks `OTEL_*` inheritance by subprocesses. Gemini: `target` `local`/`gcp`, `otlpEndpoint`, `outfile` (overrides endpoint), `useCollector`; GCP direct export to Cloud Trace/Logging/Monitoring via `OTLP_GOOGLE_CLOUD_PROJECT`. Codex: `[otel]` `exporter`, `trace_exporter`, `metrics_exporter` (`none|statsig|otlp-http|otlp-grpc`), `environment`, `span_attributes`, `tracestate`.
- **Productivity signals are edit-outcome counters**: Claude Code `lines_of_code.count`, `commit.count`, `pull_request.count`, `code_edit_tool.decision`; Gemini `lines.changed` and per-call `model_added_lines` vs `user_added_lines`; Cline `ai_output.{accepted,rejected}.*`; Copilot `edit.acceptance.count`, `edit.survival.four_gram`. All are user-acceptance measures, meaningless without a human in the loop.
- **Trajectory as the primary artifact (OpenHands).** The persisted event list plus `Metrics` is the run record; observability spans are secondary. `Metrics.diff(baseline)` gives per-phase deltas for evaluation harnesses.

## Recommendation for lablet (opinion)

1. **Adopt** the Claude Code correlation layering (`run` > `turn` > `llm request` > `tool call`, with `tool_use_id`/`call_id` shared across decision, execution and result, and a per-run monotonic `event.sequence`). Benchmark analysis is mostly joins; make them cheap.
2. **Adopt** the split "length always, content gated" pattern: emit `prompt_length`, `response_length`, `tool_input_size_bytes`, `tool_result_size_bytes`, `output_line_count` unconditionally; gate text behind one switch with a single cap and `_truncated`/`_original_length` sidecars.
3. **Adopt** the `*_safe` bounded-vocabulary companions (`tool_name_safe`, `bash_command_class`, `error_class`) as the only values allowed on metric dimensions; keep raw names on spans and events. Weaver can enforce this per attribute.
4. **Adapt** Codex `codex.turn.cost_microusd` and OpenHands `Metrics` shape for per-run summary: integer micro-USD, token buckets `input`/`output`/`cache_read`/`cache_write`/`reasoning`, and a `cache_hit_rate` derived field. Emit the summary as attributes on the root span plus one final summary record.
5. **Adapt** Gemini `gemini_cli.agent.finish` (`turn_count`, `duration_ms`, `terminate_reason`) and Codex `turn.interrupted` into lablet's run-end record; `terminate_reason` should use lablet's existing stop-reason enum.
6. **Adapt** OpenHands `llm_response_id` + `action_id` linkage for multi-tool-call responses; lablet's one-LLM-call-many-tools case needs the response id on every tool span.
7. **Adopt** the GenAI semconv names Gemini and Copilot already use (`gen_ai.operation.name`, `gen_ai.usage.*`, `gen_ai.tool.call.id`, `gen_ai.conversation.id`) as the canonical attribute names, with vendor aliases only where semconv has no term (e.g. `ttft_ms`, `first_content_ms`, `attempt`).
8. **Skip** every productivity metric (`lines_of_code`, `commit.count`, `pull_request.count`, `code_edit_tool.decision`, `ai_output.accepted`, `edit.survival`). They measure human acceptance, which a benchmark loop does not have; lablet's outcome is the task grader's verdict.
9. **Skip** identity and org attributes (`user.*`, `organization.id`, `terminal.type`, `app.entrypoint`) and approval-decision events; replace with `run.id`, `task.id`, `sample.index`, `agent.config_hash`, `model`, and `seed`.
10. **Fill the gap none of these cover**: record git commit + dirty flag of the target repo, sandbox/container id, tool subprocess CPU and wall time, dependency lockfile hash, and model/provider version string on the run root. Derived per-run metrics worth computing: tokens per turn, tool calls per turn, tool failure rate, retry count (`attempt` > 1), TTFT p50/p95, cache hit rate, wall time split into LLM wait vs tool execution vs loop overhead, and cost per successful task.
